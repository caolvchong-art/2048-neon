## 基础规则

和经典 2048 完全一致：方向键滑动，相同数字合并，目标凑出 **2048**。

## 创新玩法

### ⚡ 能量与技能

每次合并都会积攒能量（数字越大给得越多，连续合并不中断还有额外加成），能量可以换技能：

| 技能 | 消耗 | 效果 |
| --- | --- | --- |
| ⚡ 强化 | 30 | 点一个方块让它升一级（数值翻倍） |
| 💣 爆破 | 45 | 点一个方块直接移除，**冰封块也能拆** |
| 🔀 重排 | 35 | 打乱场上所有方块的位置 |
| ⏪ 回溯 | 15 | 退回上一步，最多可回溯 15 步 |

合并 `v` 得到的能量为 `max(1, log2(v) - 1)`。

### 🔥 连击倍率

一次滑动里合并 **2 次以上** 就触发连击，得分按合并次数乘算（最高 **×4**）。
连续多步都有合并会累积「连击链」，链条越长能量收入越高（每级 +10%，最多 +80%）。

### ✦ 万能块

金色的星形方块，可以和**任何**数字合并，吃掉对方后数值翻倍，用完即变回普通块。
第 8 步之后开始有 10% 概率随机出现。

两个万能块合并得到 4。

### ❄ 冰封块

冻住的方块**不能移动、也不能被合并**，会像一堵墙一样把整行/整列切断，彻底改变空间策略。

- 它**周围发生 3 次合并**就会解冻，恢复成原来的数字；
- 或者花 45 能量用爆破直接拆掉。

### 🌀 随机事件

每 **20 步**触发一次，好坏事都有可能：

| 事件 | 效果 |
| --- | --- |
| 🌧 甘霖 | 随机两块方块升级 |
| ❄ 寒潮 | 随机一块方块被冰封 |
| ⚡ 丰收 | 立刻 +40 能量 |
| 🌀 混沌 | 全场位置重排 |
| ☄ 陨石 | 随机摧毁一块方块 |

### 🔮 AI 提示

内置 expectimax 搜索 + 启发式评估（空格数 / 单调性 / 平滑度 / 最大块是否在角上），
免费告诉你它认为当前最好的一步。

### 🏆 排行榜

有两套榜单，点「🏆 排行」查看：

- **本机榜** —— 存在浏览器 `localStorage`，按 4×4 / 5×5 分开，保留前 20 条。离线可用，一局结束自动记录。
- **全球榜** —— 存在 Supabase（Postgres），按棋盘尺寸分开排，展示前 10。需要自己填昵称后手动点击提交。

![排行榜](docs/preview-leaderboard.png)

**效率分**：`分数 ÷ 步数 × 10`。它奖励高效打法而不是磨时间刷分，所以和总分是两个独立维度
（总分高不代表效率高，反之亦然）。

## ⌨️ 操作

| 操作 | 键盘 | 触屏 |
| --- | --- | --- |
| 移动 | `↑ ↓ ← →` 或 `W A S D` | 在棋盘上滑动 |

## 📦 部署到 GitHub Pages

本项目是纯静态单页，**不需要任何构建步骤**。

### 上手前先自检

```powershell
.\check-env.ps1
```

一次性检查 git / gh / 凭据 / hosts 屏蔽 / 网络可达性，并告诉你还差什么、按什么顺序解决。
（如果你在 DSH 沙箱里跑，网络那两项会显示受限，那是沙箱行为，请在你自己的终端里再跑一次。）

### 方式一：一键脚本（推荐）

```powershell
# Windows
.\deploy.ps1
```

```bash
# macOS / Linux
./deploy.sh
```

脚本会：`git init` → 提交 → 用 `gh` 创建远程仓库 → 推送 → 开启 Pages。

### 方式二：手动

```bash
git init -b main
git add .
git commit -m "feat: 2048 霓虹进化"
git remote add origin https://github.com/<你的用户名>/2048-neon.git
git push -u origin main
```

推送后在仓库 **Settings → Pages** 里把 Source 设为 **Deploy from a branch**，
分支选 `main`、目录选 `/ (root)`，保存后等一分钟即可访问：

```
https://<你的用户名>.github.io/2048-neon/
```

> ⚠️ GitHub Pages 在**私有仓库**上需要付费计划，免费账号请把仓库设为 Public。

## 🏆 全球榜后端（Supabase）

全球榜用 [Supabase](https://supabase.com)（免费额度足够）的 Postgres + 自动生成的 REST API。
**不需要任何第三方 SDK**，页面里只用原生 `fetch`。

### 为什么要这样做才安全

页面是纯静态的，所以 Supabase 的 **publishable / anon key 一定会出现在 HTML 源码里**，
任何人 F12 都能看到。这没关系 —— 这个 key 本来就是设计成公开的，
真正的权限由 **行级安全策略（RLS）** 决定：

| 操作 | 匿名访客 |
| --- | --- |
| 读取榜单 | ✅ 允许 |
| 提交成绩 | ✅ 允许 |
| 修改成绩 | ❌ 拒绝（没有 update 策略） |
| 删除成绩 | ❌ 拒绝（没有 delete 策略） |

也就是说任何人都**看得到、交得上，但改不了也删不掉**。再加上表上的 CHECK 约束
（昵称 ≤16 字符、分数上限、棋盘尺寸只能是 4/5/6），就算有人绕开页面直接调 REST API
灌脏数据，也会被数据库挡下来。

> ⚠️ **绝对不要把 `service_role` / `sb_secret_...` key 放进前端。**
> 它会**绕过 RLS**，等于数据库管理员密码。

### 搭建步骤

1. 建一个 Supabase 项目
2. SQL Editor 里执行 [`supabase/setup.sql`](supabase/setup.sql)（可重复执行，不会动已有数据）
3. 在 `index.html` 顶部改这两个常量：

```js
var SB = {
  url:   "https://<你的项目>.supabase.co/rest/v1",
  key:   "sb_publishable_...",     // 或旧的 anon JWT
  table: "leaderboard_sum"
};
```

`supabase/reset.sql` 只在需要重建表时使用（**会清空榜单**）。

> Supabase 免费项目**闲置约一周会自动暂停**，届时全球榜会加载失败并提示，
> 去控制台点一下恢复即可。本机榜不受影响。
